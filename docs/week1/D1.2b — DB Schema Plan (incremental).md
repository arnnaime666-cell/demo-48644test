# Week 1 — DB Schema Plan (incremental, Supabase reuse — zero data loss)

**Constraint:** No wipe. Every change is an incremental migration with downgrade. Each migration is `IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`.

## New / altered objects (vs 21 live tables)

| Change | SQL outline | Data impact |
|---|---|---|
| `provinces` reference (or enum) | `CREATE TABLE provinces (code text PK, name text)` + seed 13 | New table, no data move |
| `profiles.province` normalization | `ALTER TYPE` or check constraint + `UPDATE profiles SET province = normalized(province)` | In-place update — `'Ontario'` → `'ON'` where needed; row-count same |
| `tutors` province column (via join today) | `ALTER TABLE tutors ADD COLUMN province text` + backfill from `profiles` | Additive |
| Tax engine | `CREATE TABLE tax_rates (province text, hst numeric, gst numeric, pst numeric, effective_date)` | New table |
| i18n | `ALTER TABLE profiles ADD COLUMN locale text DEFAULT 'en'` + message keys elsewhere | Additive |
| Invoice province label fix | App-layer `toProvinceCode()` normalization (commit 94c8d07) — no DB change unless desired | - |
| Adjacent: PIPEDA columns already in `profiles` (`terms_accepted`, etc.) — keep | - | - |

## Migration safety

1. Take backup (D1.5) → 2. Run migration in isolated restore → 3. Row-count match → 4. Run on production isolated branch → 5. Swap.
