## Principles

- One deployable Next.js 16 App Router app (until pressure to split).
- Domain-oriented server logic: `admin`, `tutors`, `family`, `payments`, `sessions`, `notifications`.
- Keep route URLs stable; use aliases (`/family/*` ↔ `/student/*`) not breaks.
- Centralize runtime config (`platform/config/runtime.ts`) and shared integrations (`src/lib/*`).
- Supabase migrations are the DB source of truth; `supabase/schema.sql` is historical only.

## Flow mapping

- **admin** — tutor queue review/approve/reject, account controls, disputes, PIPEDA, financial reports, audit log.
- **family** — parent/child onboarding, booking, progress, learning goals, premium upsell.
- **payments** — checkout → Stripe PaymentIntent → webhook → invoice + escrow → payout (48h, retry 3×).
- **sessions** — lifecycle, cancellation 24h, dispute 48h, join window 5/60, feedback, recording gate, whiteboard.
- **tutors** — profile, availability, documents (flagged/approved), onboarding via Stripe Connect, earnings.
- **notifications** — session reminders (22–26h + 90m), reapplication check 30 days.
